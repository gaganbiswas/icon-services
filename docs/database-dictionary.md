# Database dictionary

PostgreSQL 17 · Prisma 7 · source of truth: `packages/database/prisma/schema.prisma`
and `packages/database/prisma/migrations/`. Updated: Phase 5 (2026-11-18).

## Conventions

| Rule | Detail |
|------|--------|
| Keys | UUIDv7 primary keys (`uuid`), generated by Prisma |
| Names | `snake_case` tables and columns |
| Time | `timestamptz(3)`, always UTC; display in local time zone |
| Money | `NUMERIC(19,4)` + decimal library; serialised as strings (ADR 0005). None yet |
| Tenancy | Every tenant-owned row has `organization_id`; link tables repeat it and use **composite foreign keys** so cross-organization links are impossible at database level |
| Concurrency | Mutable aggregates carry `version`; updates use `WHERE version = :expected` |
| Deletion | Users, roles, branches, sessions are deactivated/revoked — not deleted. `audit_logs` is append-only (trigger) |
| Secrets | Passwords stored as Argon2id PHC strings; refresh and set-up tokens stored only as SHA-256 hex |

## Tables (Phase 2)

### `organizations`
Legal/business entity. `code` unique (`^[A-Z0-9][A-Z0-9_-]{0,19}$`). `legal_name`, `default_currency` (ISO 4217),
`timezone` (IANA), `country_code` (ISO 3166-1) are **nullable until confirmed by the owner**.

### `branches`
`organization_id` → organizations. Unique `(organization_id, code)`. Address/contact columns nullable. `is_active`.

### `users` (staff)
| Column | Notes |
|--------|-------|
| `email` / `email_normalized` | Display value / lower-cased login key, **globally unique**, checked `= lower(btrim(...))` |
| `password_hash` | Argon2id; `NULL` until password set-up is completed |
| `must_change_password` | Forces change before other routes (`PASSWORD_CHANGE_REQUIRED`) |
| `failed_login_count`, `locked_until` | Lockout (ADR 0010); count ≥ 0 |
| `is_active` | Deactivation revokes sessions |
| `version` | Optimistic concurrency (≥ 1) |

### `permissions`
Global catalogue; `code` unique. Seeded from `packages/contracts/src/permissions.ts` by `ensurePermissions` (idempotent, safe in production).

### `roles`, `role_permissions`
Per-organization roles; `(organization_id, code)` unique; code `^[A-Z][A-Z0-9_]{1,49}$`. `is_system` marks seeded roles (`ensureSystemRoles`).
`role_permissions (role_id, permission_id)` PK.

### `user_roles`, `user_branch_access`
Link tables with `organization_id`; composite FKs `(organization_id, user_id) → users`, `(organization_id, role_id) → roles`,
`(organization_id, branch_id) → branches`. Record `assigned_by_id` / `granted_by_id`.

### `auth_sessions`
One per sign-in (= refresh-token family). `expires_at` absolute (> `created_at`); `revoked_at` and `revoked_reason`
set together (`LOGOUT`, `REFRESH_TOKEN_REUSE`, `PASSWORD_CHANGED`, `PASSWORD_RESET`, `USER_DEACTIVATED`, `ADMIN`).
`ip_address`, `user_agent` only when `AUDIT_STORE_CLIENT_METADATA=true`.

### `refresh_tokens`
`token_hash` unique SHA-256 hex; `used_at` set atomically on rotation (`UPDATE … WHERE used_at IS NULL`); a second use
revokes the session.

### `password_setup_tokens`
One-time tokens: `purpose ∈ {INITIAL_SETUP, ADMIN_RESET}`, `expires_at`, `used_at`, `revoked_at` (superseded),
`issued_by_id`.

### `audit_logs` (append-only)
`actor_type ∈ {USER, SYSTEM, ANONYMOUS}`; `actor_user_id` present iff `USER` (CHECK). `action` (dotted, e.g.
`auth.login.succeeded`, `user.deactivated`, `role.updated`), `entity_type`, `entity_id`, redacted `before`/`after` JSON,
`reason`, `request_id`, optional `ip_address`/`user_agent`.
Trigger `audit_logs_no_update_or_delete` raises on `UPDATE`/`DELETE`. Production DB role must not have `TRUNCATE`.
Indexes: `(organization_id, created_at DESC)`, `(entity_type, entity_id)`, `(actor_user_id, created_at DESC)`.

## Tables (Phase 3, ADR 0012)

| Table | Purpose / key rules |
|-------|---------------------|
| `business_settings` | Per-organization JSON settings, validated by Zod (`packages/contracts/src/settings.ts`); code defaults apply when absent. Unique `(organization_id, key)` |
| `number_sequences` | Counters for job numbers / customer codes. Incremented by one atomic `INSERT … ON CONFLICT DO UPDATE … RETURNING` inside the business transaction. Unique `(organization_id, branch_scope, document_type, period_key)`; `branch_scope = '-'` for organization-wide |
| `idempotency_keys` | Unique `(actor_key, operation, key)`; stores request SHA-256 and the response for replay; 7-day expiry |
| `customers` | Customer code unique per org; `phone_e164` CHECK `^\+[1-9]\d{6,14}$` plus display value; trigram index on `lower(name)`; status ACTIVE/ANONYMIZED; `source` INTAKE_STAFF/CUSTOMER_APP/WEB_PORTAL; `version` |
| `customer_addresses` | One `BILLING` and one `SERVICE` row max per customer |
| `customer_consents` | Append-only grants; withdrawal sets `withdrawn_at`. Partial unique index: one active row per (customer, channel, purpose). Policy version from settings |
| `asset_categories` | Per-org categories (seeded DESKTOP, LAPTOP, PRINTER, MONITOR, OTHER) |
| `assets` | Composite FKs to customer and category in the same org; `serial_normalized` index (not unique — duplicates warned); `attributes` JSONB object validated per category |
| `files` | Random `storage_key`; MIME sniffed from content; SHA-256; classification PERSONAL/INTERNAL/DOCUMENT; single uploader (staff or customer) |
| `service_jobs` | Unique `(organization_id, job_number)`; composite FKs to branch/customer/asset in same org; status enum incl. `AWAITING_DEVICE`; CHECKs: on-site requires address, received jobs have `received_at`, exactly one creator (staff or customer) |
| `job_status_history` | Append-only (trigger rejects UPDATE/DELETE) |
| `job_attachments` | Job ↔ file with category and visibility (INTERNAL/CUSTOMER) |
| `documents` | Generated documents with immutable `snapshot` JSON; unique `(entity_type, entity_id, document_type, layout, version)`; trigger rejects UPDATE/DELETE |
| `customer_otp_challenges` | HMAC-SHA256 code hash, attempts, expiry, consumed time |
| `auth_sessions` (changed) | `subject_type` STAFF/CUSTOMER; exactly one of `user_id` / `customer_id` (CHECK) |

## Tables (Phase 4, ADR 0013)

| Table | Purpose / key rules |
|-------|---------------------|
| `job_assignments` | Assignment history; ended (never deleted). Partial unique index: one active row per (job, technician) |
| `diagnoses` | Symptom, findings, root cause, recommendation, staff-only `internal_notes`. Append-only (trigger) |
| `work_logs` | Work entries / notes with `visibility` INTERNAL or CUSTOMER (≤ 500 chars), optional duration 1–1440 min. Append-only (trigger) |
| `service_jobs` (changed) | Completion record `repair_summary`, `qc_checklist`, `completed_by_id`, `completed_at` — all set or all null (CHECK) |
| `notification_outbox` | Notification intent written in the business transaction; unique `idempotency_key`; status PENDING/PROCESSING/COMPLETED/FAILED/DEAD/SKIPPED; `attempts`, `next_attempt_at`, `locked_until` lease; `branch_id` for scoping |
| `notification_deliveries` | Per channel/attempt result: ACCEPTED (provider took it — not delivery), FAILED, SKIPPED_NO_CONSENT, SKIPPED_NO_ADDRESS; DELIVERED/READ only from provider callbacks (Phase 10). Unique (outbox, channel, attempt) |

## Tables (Phase 5, ADR 0014)

| Table | Purpose / key rules |
|-------|---------------------|
| `estimates` | Versioned per job (unique `(job_id, version)`); partial unique index: one DRAFT-or-SENT per job; money `NUMERIC(19,4)`; CHECKs `total = subtotal − discount_total = customer_payable + covered`, sent ⇒ `sent_at` + `valid_until`, decided ⇒ `decided_at`; **trigger: immutable after DRAFT** (only status / decision time / row version change, SENT → APPROVED/REJECTED/SUPERSEDED/WITHDRAWN), never deleted. `tax_treatment = NOT_CONFIGURED` |
| `estimate_lines` | Position, type, description, SKU snapshot, quantity, unit, unit price, discount, coverage (CUSTOMER_PAY/WARRANTY/GOODWILL), `line_total = quantity × unit_price − discount` (CHECK); trigger allows changes only while the estimate is DRAFT |
| `estimate_decisions` | One per estimate; decision, method (CUSTOMER_APP/APPROVAL_LINK), customer, estimate version, approved amount snapshot, terms accepted + SHA-256 of terms, comment, optional IP/user agent; append-only |
| `estimate_approval_links` | Token SHA-256 (unique), expiry, used / revoked time; single-use |

## Seeds

| Command | Environment | Effect |
|---------|-------------|--------|
| `ensurePermissions` / `ensureSystemRoles` (library) | any | Idempotent catalogue + system roles per organization |
| `bun run db:seed:dev` (packages/database) | development only (refuses `NODE_ENV=production`) | Placeholder org `DEV`, branch `DEV-01`, Super Admin from `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD` |
